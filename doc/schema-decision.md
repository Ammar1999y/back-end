# قرار اختيار مكتبة التحقق: Zod · Zod/mini · TypeBox · Valibot

> ملخّص مبني على: بيانات هذا المشروع (`bench.json`)، جدول مقارنة Sury، واختبارات Elysia/Hono الواقعية على Bun (25 → 1k → 40k مسار).

---

## ‎١) تصحيح جوهري: Valibot لا تستخدم `eval`

Valibot هي **eval-free** بالتصميم — لا تستخدم `new Function`/`eval` إطلاقًا. لذلك هي **الأنسب** للـ CSP الصارم، وليست ضدّه.

### من يستخدم `new Function` فعلًا؟

| المكتبة | تستخدم `new Function`/eval؟ | تعمل تحت CSP صارم؟ |
|---------|:---:|:---:|
| **Valibot** | ❌ لا (eval-free) | ✅ دائمًا |
| **TypeBox** | افتراضيًا لا · مع `TypeCompiler` نعم (opt-in) | ✅ افتراضيًا / ❌ مع الـ compiler |
| **Zod 4** | نعم افتراضيًا (JIT) · يمكن إيقافه (`jitless`) | ❌ افتراضيًا / ✅ مع jitless |
| **Zod/mini** | مثل Zod 4 (JIT، قابل للإيقاف) | مثل Zod |
| **ArkType** | نعم (opt-out) | ❌ افتراضيًا |
| **Sury** | نعم | ❌ |

**الأدلة:**
- جدول Sury، صف *Eval-free*: **Valibot ✅** (الوحيدة بعلامة صريحة)، Sury ❌، Zod ⭕ opt-out، TypeBox ⭕ opt-in، ArkType ⭕ opt-out.
- تحذير Sury (سطر 37): `new Function` تستخدمها **"TypeBox, Zod@4 and ArkType"** — **Valibot غير مذكورة**.
- بيانات المشروع: توجد إدخالات `optimizeType=jit` لـ zod وtypebox وarktype، وإدخال `zod … note=jitless`؛ بينما Valibot دائمًا `optimizeType=none`.

### لماذا هذا مهم؟
سبب أن Valibot "أبطأ" في تكرار التحليل (81 ops/ms مقابل TypeBox 256) هو **نفسه** سبب أمانها مع CSP: لا JIT، تفسّر المخطّط في كل استدعاء. لو استخدمت eval لكانت سريعة. المقايضة واحدة: **أمان CSP + حجم صغير ↔ إنتاجية أقل في الحلقة الساخنة**.

**قاعدة CSP:** واجهة أمامية بمتصفح وCSP صارم يمنع `unsafe-eval` → **Valibot** (أو TypeBox/Zod في وضع jitless/بدون compiler).

## ‎٢) توضيح معنى "التوسّع" (scaling)

المقصود **ليس** تعدّد الخوادم أو توزيع الحمل، بل **عدد المخطّطات/المسارات داخل تطبيق واحد** — وهو ما تقيسه اختبارات 25 → 1k → 40k مسار في عملية واحدة: كيف ينمو **الحجم + الإقلاع + الذاكرة** كلما أضفت مخطّطات.

### الأدلة عند 40k مسار (بلا AOT)

| المكتبة | الحزمة | الإقلاع | الذاكرة |
|---------|:---:|:---:|:---:|
| **TypeBox** | 818KB (ثابت من 25→40k) | 135ms | **150MB** |
| **Valibot** | **317KB** | 141ms | 173MB |
| **Zod** | 834KB | **995ms** | **1133MB** ⚠️ |

### مع AOT عند 40k مسار

| المكتبة | الحزمة | الإقلاع | الذاكرة |
|---------|:---:|:---:|:---:|
| **AOT Valibot** | **983KB** | **161ms** | **184MB** |
| AOT TypeBox | 27.8MB ⚠️ | 381ms | 234MB |
| AOT Zod | 1.5MB | 1.0s | 1141MB ⚠️ |

**الاستنتاج:**
- **Zod تنفجر ذاكرتها** مع كثرة المخطّطات (>1GB) — تجنّبها للمسارات الكثيرة.
- **TypeBox** حجمها ثابت (بيانات لا كود)؛ ممتازة عند التوسّع بلا AOT، لكن **AOT يُفجّر حجمها** عند مقياس خيالي (تُضمّن كل مخطّط كـ كود).
- **Valibot توازن الأفضل عند التوسّع** (أصغر حزمة، ذاكرة معقولة، الأفضل مع AOT) — لذلك قال المنشور: *"Elysia + Valibot الأسرع لإطار+مكتبة تحقّق"*.

## ‎٣) القرار النهائي لكل مكتبة

### 🟦 TypeBox — الخلفية عالية الأداء + Elysia + JSON Schema
**استخدمها عندما:**
- تستخدم **Elysia / Bun** → المُحقّق الأصلي (أداء صفري، tree-shaking عبر AOT، حجم ثابت مهما كثُرت المسارات).
- تحتاج **JSON Schema / OpenAPI / Swagger** أصلًا (الأفضل هنا 👑).
- مسار خادم ساخن يتطلّب **أقصى إنتاجية تحقّق** (JIT — 256 ops/ms، الأسرع في المشروع).

**تجنّبها عندما:** واجهة أمامية عادية (DX مُسهِب)، أو AOT مع عدد مسارات ضخم (الحجم ينفجر).

### 🟩 Valibot — الواجهة الأمامية / Edge / Serverless / التوسّع / CSP
**استخدمها عندما:**
- **Frontend / Edge / Serverless / Cloudflare Workers** → أصغر حزمة (1.9KB نواة · 61KB في Hono مقابل 579KB لـ Zod).
- **CSP صارم** (تمنع eval) → eval-free بالكامل.
- **cold-start حسّاس** → الأسرع في "أنشئ وحلّل مرة واحدة" (287 ops/ms) وأقل ذاكرة عند التوسّع.
- **عدد مخطّطات ضخم** → يتوسّع الأفضل حجمًا وذاكرةً.

**تجنّبها عندما:** حلقة خادم تكرّر تحليل نفس المخطّط ملايين المرات (81 ops/ms، أبطأ من JIT)، أو تحتاج نظامًا بيئيًا ضخمًا جاهزًا.

### 🟥 Zod — تطبيق عام، DX ونظام بيئي أولًا
**استخدمها عندما:**
- تريد **أفضل تجربة مطوّر وأوسع تكاملات** (tRPC، React Hook Form، Drizzle، Prisma…) وأكبر مجتمع/توثيق.
- **الخادم لديه ذاكرة وفيرة** والحجم ليس قيدًا، وعدد المخطّطات معتدل.
- **الفريق والصيانة** طويلة الأمد أهم من آخر ميلي ثانية.

**تجنّبها عندما:** Edge/Serverless (حزمة كبيرة + cold-start)، أو **مسارات/مخطّطات كثيرة** (الذاكرة تنفجر: 95MB عند 1k، >1GB عند 40k).

### 🟨 Zod/mini — الوسط: دلالات Zod ونظامه بحجم أصغر
**استخدمها عندما:**
- لديك **كود Zod قائم** وتريد نقله للواجهة/Edge **دون تغيير المكتبة** — يبقى ضمن عائلة Zod بحجم ~5KB بدل 17KB.
- تريد **توافق دلالات Zod** (نفس سلوك التحقّق/الأخطاء) بـ tree-shaking أفضل، وتقبل **DX أضعف** (API دالّي: `string()` بدل `z.string()`).

**تجنّبها عندما:** مشروع جديد بلا التزام بـ Zod → **Valibot أصغر وأنضج في هذا الدور**. زِنها فقط كجسر داخل نظام Zod. (وللـ CSP الصارم استخدم وضع jitless.)

## ‎٤) مخطّط الاختيار السريع

```
تستخدم Elysia/Bun؟ ───────────────────────► TypeBox
        │ لا
        ▼
Edge / Serverless / Frontend / CSP صارم / حجم مهم؟ ─► Valibot
        │ لا
        ▼
لديك كود Zod قائم وتريد تصغيره فقط؟ ────────► Zod/mini
        │ لا
        ▼
تطبيق عام، DX ونظام بيئي أولًا، ذاكرة مُرفَّهة؟ ──► Zod
```

## ‎٥) الخلاصة في سطر
- **Elysia/Bun أو JSON Schema** → **TypeBox**
- **المتصفح / Edge / التوسّع / الحجم / CSP** → **Valibot**
- **DX ونظام بيئي وخادم مُرفَّه** → **Zod**
- **جسر لتصغير كود Zod قائم** → **Zod/mini** (وإلا فـ Valibot)

### تنبيهات على مصادر الأرقام
- جدول Sury منشور من **منافِس** (انحياز مقصود): يقيس على مخطّط تافه `{foo: string}` يضخّم فجوة JIT (×58)؛ على مخطّط واقعي تنكمش إلى ~×3.
- اختبارات Elysia/Hono من منشور تويتر (Bun) — واقعية لكن تخصّ سياق Bun/Elysia تحديدًا.
- أرقام `ops/ms`: أعلى = أسرع · أرقام `ms`: أقل = أسرع.
